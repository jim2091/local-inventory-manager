# 재고관리 프로그램 v1.0.1

## 개요

v1.0.0의 업무 기능과 화면 구성을 유지하면서 Excel 저장·복구 안정성, 거래 데이터 보존, 입력 검증과 확인 UI를 개선했습니다. 작업 대상은 Work에 첨부된 프로젝트 ZIP의 복사본이며, 사용자 PC의 저장소나 GitHub를 수정하지 않았습니다.

코드 기준: `local-inventory-manager-release-v1.0.1(1).zip`. SHA-256: `9c7b42a0a64db5aac23796f3e0457b0780c4bb666a40db6fa486cc3972bfc704`.

수정 전 fingerprint 확인: `name=local-inventory-manager`, `author=ljb`, 최초 버전 `1.0.0`, 업무 메뉴 9개, 지정된 기존 컴포넌트 5개, 조회 필터·정렬·합계·페이지·내보내기, 재고조정 IPC, 자동 백업/정리 설정, Windows 창 크기와 NSIS 설정이 모두 있었습니다. 과거 `inventory.zip` 또는 이전 Work 결과물의 코드는 사용하지 않았습니다.

## 주요 변경사항

### 데이터 저장 안전성

완성된 데이터 검사 → 같은 폴더의 임시 Excel 작성 및 디스크 반영 → 임시 파일 재검사 → 현재 정상 데이터의 직전 사본 보존 → 파일 이름 변경으로 교체 → 최종 재검사 순서입니다.

교체를 시도한 상태와 실제 교체가 완료된 상태를 따로 추적합니다. 임시 파일 작성·검사 또는 직전 사본 작성에 실패하면 현재 데이터를 건드리지 않습니다. 실제 교체 이후의 검증 실패만 바로 직전 정상본으로 복원합니다. 오래된 사본이 있다는 이유만으로 무조건 덮어쓰지 않습니다. 실패한 파일과 재사용할 임시 파일은 `recovery/`에 보관하며, 실패 시 복구 후보를 일괄 삭제하지 않습니다.

### 비정상 종료 복구

시작 시 현재 파일, 저장 중이던 파일, 이전 정상 파일을 모두 확인합니다. 현재 파일이 없거나 손상되었는데 사본이 있으면 첫 실행 화면보다 복구 화면을 우선 표시합니다. 후보의 시각과 거래 수를 보여주며 사용자가 선택합니다. 사용 가능한 후보가 없으면 백업 복원 또는 다시 확인을 안내합니다.

현재 파일이 정상이면 이를 사용합니다. 과거 사본이나 남아 있는 저장 중 파일로 자동 교체하지 않습니다. 화면에는 “이전 정상 데이터”, “저장 중이던 데이터”로 안내합니다.

### 시작 시 데이터 검증

`입출고내역`, `품목`, `매출거래처`, `매입거래처`, `재고조정`, `설정`의 존재와 필수 헤더를 검사합니다. 품목/거래처 코드·이름·중복, 품목의 가격·재고 숫자, 거래/조정 번호·날짜·수량, 거래구분·취소여부 등을 검사합니다. 거래처 중복은 각 시트 내부에서만 판단합니다.

현재 품목 목록에 없는 과거 품목은 경고로 처리해 기록을 보존합니다. 단, 해당 품목이 없으면 기존 정책대로 거래 취소로 재고를 되돌릴 수 없습니다.

### 거래 규격/단위 Snapshot

신규 입출고에 저장 당시 품목의 규격·단위를 기록합니다. 이후 품목 수정이 과거 거래에 영향을 주지 않습니다. 조회·Excel 내보내기에도 이 거래 값을 사용합니다.

### v1.0.0 Migration

거래의 규격/단위 열이 없을 때만 현재 품목 정보로 보완합니다. 품목이 없으면 빈 값입니다. 기존 거래번호·일자·구분·수량·단가·공급가액·부가세·합계·취소상태와 품목 현재재고를 재계산하지 않습니다. 이전 정상 파일을 먼저 보존하며, 두 번째 실행부터는 같은 파일을 다시 저장하지 않습니다.

이 보완 값은 **현재 품목 정보**이므로 실제 과거 거래 당시 값과 다를 수 있습니다. 기존 Excel 가져오기는 원본 거래의 규격/단위를 직접 사용합니다.

### 음수 출고 사전 확인

Main에서 최종 재고를 계산해 음수가 예상되면 저장하지 않고 확인 요청을 반환합니다. 확인창에는 현재재고·출고수량·예상재고를 표시합니다. 취소 시 거래·재고·백업은 변경하지 않습니다. 승인 플래그와 확인 당시 재고를 Main에서 다시 확인하며, 재고가 달라졌다면 재확인을 요구합니다.

### 입출고 조회 개선

화면의 번호 열만 제거했습니다. 내부 거래번호와 거래 취소 기능은 유지합니다. 규격/단위 열 및 정렬을 추가했습니다. 날짜 최신순 및 같은 값의 거래번호 내림차순 정렬, 모든 필터, 30/50/100건 페이지, 전체 보기, 조회 결과 합계, 내보내기와 폴더 열기를 유지했습니다.

### 삭제 확인

품목/거래처 삭제 전에 코드와 이름을 표시합니다. 확인창은 취소 버튼에 기본 초점을 두고 Escape와 키보드 이동을 지원합니다. 거래·재고조정에 사용된 품목, 거래에 사용된 거래처의 코드 변경/삭제 차단은 Main에 그대로 남아 있습니다.

### 입력 검증

품목 가격은 빈 값 또는 유한한 0 이상의 숫자만 허용합니다. 입출고 수량은 1 이상의 정수, 단가는 0 이상이며 거래유형·품목·거래처·날짜를 검증합니다. 재고조정 실제수량은 0 이상 정수, 증감수량은 음수를 허용하는 0이 아닌 정수입니다. 실제수량 모드는 Main의 최신 재고로 증감을 다시 계산합니다. 현재재고는 품목 폼에서 계속 readOnly이며 Main 품목 수정에서도 기존 값을 유지합니다.

### 백업/복원

수동 백업, 하루 첫 변경 시 자동 백업, 자동 백업 30개 유지 정리, 폴더 열기 및 JSON 설정을 유지합니다. 백업 이름 충돌을 줄였습니다. 복원 대상의 6개 시트·필수 헤더·데이터를 먼저 검사하고, 정상 현재 데이터를 보존한 후 안전 저장 경로로 복원합니다. v1.0.0 백업은 메모리에서 보완한 뒤 저장하며 백업 원본은 수정하지 않습니다.

### 메시지 UX

품목/거래처 등록·수정·삭제 성공 메시지가 폼 초기화 때문에 사라지지 않도록 수정했습니다. Main과 Preload가 성공/오류 응답을 일관되게 처리해 파일 접근 오류를 쉬운 한국어로 표시하고 IPC 접두사·운영체제 오류·내부 경로가 그대로 나오지 않도록 했습니다.

### 첫 실행 UI

기존 `FirstRunSetup.jsx`를 개선했습니다. 기존 Excel 가져오기와 새로 시작을 두 선택 영역으로 표시하고, 공통 처리 잠금으로 중복 실행을 막습니다. 처리 중 상태와 오류를 표시하고 완료 후 시작 검사를 다시 기다립니다. 복구 대상이 있으면 새 빈 파일 생성보다 복구를 우선합니다.

### 테이블 UI

기존 사이드바·카드·색상·업무 화면 전환 구조와 전체 CSS를 유지했습니다. 조회 표를 13개 열에 맞추어 조정하고 짧은 열을 축소했습니다. 거래처/품목 코드 표시와 취소 상세 보기를 유지하며 긴 이름·규격·취소사유는 도움말로 확인할 수 있습니다. 숫자 정렬, 키보드 초점, 1280px 이하 콘텐츠 여백을 조정했습니다. 좁은 창의 표 가로 스크롤은 유지됩니다.

창 설정은 1280×800, 최소 1100×700 그대로입니다. 실제 화면 배치와 Windows 배율별 사용성은 이 환경에서 렌더링 검증하지 못했습니다.

### 검색

앞부분 일치로 제한되어 있던 입출고 조회 검색을 공백 제거·대소문자 무시·부분 문자열 검색으로 맞췄습니다. 기존 검색 필드를 제거하지 않았습니다. 입출고 등록의 품목 자동완성은 브랜드·규격도 검색합니다.

### 코드 품질

원본에서 확인한 lint 오류 8개를 해결했습니다. 중복 반환, 사용하지 않는 함수, props 검증, 비동기 로더 관련 Hook 오류를 수정했습니다. ESLint 설정이나 규칙을 끄지 않았으며 새 의존성을 추가하거나 기존 의존성을 업그레이드하지 않았습니다. 기존 스타일을 대량 재포맷하지 않아 Prettier 경고는 남아 있습니다.

## 기존 기능 보존 확인

아래의 “자동”은 실제 Main 데이터 함수를 임시 폴더의 Excel 파일에 실행한 검사이며 Windows GUI 실행을 뜻하지 않습니다.

| 기능 | 보존 확인 및 검증 범위 |
| --- | --- |
| 입고·출고·출고반입 / 취소 | 자동: 세 유형의 재고 증감, 취소, 중복 취소 차단 |
| 조회 필터·정렬·100건 페이지·전체 보기·합계 | 원본 대비 JSX/계산 코드 및 빌드 검사. 클릭 테스트 미실시 |
| 조회 Excel 내보내기 / 폴더 | 자동: 거래 snapshot·합계가 있는 실제 Excel 생성, 폴더 API 호출 경로 |
| 재고 현황 | 기존 컴포넌트 바이트 동일, 품목 조회 경로 유지. 화면 미실행 |
| 재고 조정 / 조정 내역 | 자동: 실제수량/증감수량 모드, 내역 조회, 음수·정수 검증 |
| 품목 CRUD | 자동: 등록·수정·삭제 제한, 중복, 가격, 현재재고 보존 |
| 거래처 CRUD / 상세 열 | 자동: 양쪽 거래처 시트 14개 열+추가 열 보존, 등록·수정·삭제 |
| 재고 검사 | 자동: 조정 반영 정상 일치, 불일치 탐지, 자동 수정하지 않음 |
| 수동/자동 백업·설정·정리·복원 | 자동: 하루 한 번 생성, 자동 백업 30개 정리, 일반 Excel 거부, v1.0.0 복원 |
| 백업 폴더 열기 | shell 호출 대상 확인. 실제 Windows 탐색기 미실행 |
| 기존 Excel 가져오기 | 자동: 원본 XLSM 변환 및 해시 불변, 추가 거래처 열, 취소 시 미변경 |
| 첫 실행 두 선택 / 데이터 복구 | 데이터 생성·가져오기·복구 Main 경로 자동 검사. 화면 선택은 코드 검사 |

기존 39개 파일 모두 보존, 업무 메뉴 9개 보존, 기존 IPC 25개 보존 및 `data-file:recover` 1개 추가. 기존 `FirstRunSetup.jsx`, `ExistingExcelImporter.jsx`, `InventoryAdjustment.jsx`, `InventoryStatus.jsx`, `common/DateInput.jsx` 모두 유지했습니다. `BackupManager.jsx`, `InventoryChecker.jsx`, `InventoryStatus.jsx`, `ExistingExcelImporter.jsx`는 원본과 동일합니다.

## Excel 데이터 구조 변경

`입출고내역`의 `품목명` 뒤에 `규격`, `단위`를 추가했습니다.

```text
거래번호 / 일자 / 구분 / 거래처코드 / 거래처명 / 품목코드 / 품목명 /
규격 / 단위 / 수량 / 단가 / 공급가액 / 부가세 / 합계 / 취소여부 / 취소일시 / 취소사유
```

다른 기본 시트는 기존 스키마를 유지합니다. 거래처의 실제 14개 열은 다음과 같습니다.

```text
코드 / 구분 / 유형 / 거래처명 / 사업자(주민)번호 / 대표자명 /
사업장주소1 / 업태 / 종목 / 전화 / 팩스 / 휴대폰 / 홈페이지주소 / 실제주소1
```

거래처 저장은 기존 행을 바탕으로 요청된 필드만 바꾸고, 실제 헤더와 기본 헤더의 합집합으로 기록합니다. 기본 스키마 밖의 추가 열도 다른 행의 값과 함께 유지합니다. 가져오기에서도 이름이 있는 추가 거래처 열을 보존합니다.

## 기존 v1.0.0 데이터 호환 방법

1. 기존 데이터 위치 `문서/재고관리 프로그램/재고관리데이터.xlsx`를 그대로 사용합니다.
2. v1.0.1 시작 시 검사 후 규격/단위가 없으면 한 번만 보완합니다. 보완 직전 파일은 `재고관리데이터.prev.xlsx`에 보존됩니다.
3. 정상 파일이 없거나 손상되면 복구 화면에서 이전 정상 데이터 또는 저장 중이던 데이터를 선택합니다. 일반 백업에서도 복원할 수 있습니다.
4. v1.0.0 백업 복원은 기존 백업 화면을 이용합니다. 백업 원본은 유지됩니다.
5. 과거 VBA Excel은 기존 가져오기에서 선택합니다. 기존의 2행 거래 헤더 매핑을 검증하며 원본 규격/단위를 그대로 가져옵니다. 기존 출고반입 음수수량을 양수로 이관하는 정책은 유지하고 역사적 금액은 재계산하지 않습니다.

`prev`는 매 정상 저장마다 바뀌는 직전 사본입니다. 장기 보관은 기존 수동/자동 백업을 사용합니다. v1.0.1 데이터 파일을 이전 실행 파일로 다시 쓰는 하위 호환은 보장하지 않습니다.

## 삭제한 파일

없음. 고정 열만 쓰던 내부 `clientRowToArray` 함수는 실제 헤더를 보존하는 `writeClientRows`로 대체했습니다. 기존 업무 기능을 제거한 것은 아닙니다.

원본 대비 대형 파일은 Main 4,091행 → 4,082행, CSS 3,753행 → 3,763행, 입출고 조회 2,246행 → 2,231행입니다. 전체 파일 재작성이나 기능 축소 없이 관련 변경 부분을 diff로 검토했습니다.

### 실제 실행 테스트

Node 테스트에서 **실제 `src/main/index.js` 데이터 함수**를 실행하고 임시 Documents 폴더에 실제 Excel을 읽고 썼습니다. Electron의 app/dialog/shell/IPC 등록은 대역으로 바꿨으며 업무 로직은 대체하지 않았습니다.

총 **22개 통과 / 실패 0 / 건너뜀 0**. 저장 전 4개 실패 지점과 교체 후 검증 실패·복원 실패를 주입했습니다. SHA-256으로 현재 파일 보존·복원 및 원본 미변경을 확인했습니다. 실제 Excel 잠금이나 전원 차단을 재현한 것은 아닙니다.

첨부 XLSM은 거래 **289건**, 품목 **64건**, 매출거래처 **67건**, 매입거래처 **6건**을 변환했습니다. 거래별 규격·단위·수량·단가·금액과 품목 현재재고를 비교했고 원본 파일 해시는 동일했습니다. 업무 원본 파일은 결과 ZIP에 포함하지 않습니다.

재실행 명령:

```bash
npm ci
npm test
npm run lint
npm run build
```

`npm test` 단독은 외부 실제 XLSM 테스트 1개를 건너뜁니다(나머지 21개는 자체 임시 데이터). 실제 원본도 검사하려면 `INVENTORY_LEGACY_FIXTURE` 환경 변수에 파일 경로를 지정합니다. 예를 들어 Windows PowerShell:

```powershell
$env:INVENTORY_LEGACY_FIXTURE = 'D:\검증자료\기존재고.xlsm'
npm test
```

## Work 환경에서 확인하지 못한 내용

- Windows에서 `npm run dev`, 실제 Electron 창/Preload 격리/IPC 전송의 통합 동작.
- 1280×800 및 1100×700, Windows 100/125/150% 배율에서 표/자동완성/달력/확인창 배치.
- 필터/정렬/100건 페이지/전체 보기/합계/취소 상세와 모든 버튼의 실제 클릭 동작.
- Excel이 파일을 열어 둔 실제 Windows 잠금, 백신 간섭, 디스크 부족, 전원 차단.
- Windows 탐색기·파일 선택창 및 NSIS 설치/업데이트 후 실행.

브라우저 기반 화면 검증도 시도했으나 실행 파일이 없고 다운로드가 시간 초과되어 시작하지 못했습니다. 화면 실행·스크린샷 검증에 성공했다고 보지 않습니다. Windows에서 위 항목을 확인한 뒤 실제 사용 환경에 반영해야 합니다.

## 알려진 제한사항

- 기존 서식 경고가 남아 있습니다. 자동 검사 통과가 GUI 무결함을 의미하지 않습니다.
- v1.0.0 거래의 규격/단위 보완은 현재 품목을 기준으로 하며, 과거 시점의 사실을 복원하지 못합니다.
- 손상 파일이나 복구 후보가 모두 유효하지 않으면 자동 복구할 수 없습니다. 보존된 원본·백업을 이용해야 합니다.
- 실패 사본을 보관하는 `recovery/`는 자동 정리하지 않습니다. 불필요한 사본의 판단과 정리는 사용자가 보존 필요성을 확인한 뒤 수행합니다.
- 프로그램이 관리하는 Excel은 값 중심 데이터입니다. 임의로 추가한 매크로·서식·외부 참조·수식의 보존까지 지원 범위를 확장하지 않았습니다.
- 한 PC/한 사용자 운영 정책입니다. 다중 프로세스·외부 Excel 동시 편집의 충돌 병합 기능은 없습니다.
- 처리 결과가 불분명한 저장 실패 후에는 재실행하여 실제 거래를 확인한 뒤 재등록해야 합니다.

## v1.0.1에서 변경하지 않은 범위

Electron/React/JavaScript, 로컬 `.xlsx`와 JSON, React → inventoryApi → Preload → IPC → Main 구조, Documents 데이터 위치, 기존 9개 메뉴와 업무 정책을 유지했습니다. 로그인·권한·DB·서버·클라우드·다중 PC·모바일·새 UI 프레임워크·자동 업데이트는 도입하지 않았습니다.

`electron-builder.yml`은 원본과 바이트 단위로 동일합니다. `productName: 재고관리 프로그램`, `InventoryManager`, Windows NSIS 설정을 유지했습니다. 원본 package.json에 이미 있던 비Windows 빌드 명령/스캐폴딩 파일을 새로 추가한 것은 아니며, 이번 작업의 지원 대상은 Windows뿐입니다.

결과 ZIP에서 node_modules, out, dist, .git, 캐시, 실제 업무/테스트 Excel 및 임시 복구 파일을 제외했습니다. 사용자 저장소에 반영하는 작업은 별도로 수행하지 않았습니다.
